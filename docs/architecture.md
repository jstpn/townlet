# Architecture

Townlet is a single-page Vite app with no backend. One `Game` object owns a deterministic `Sim`, a Three.js renderer, the input tools and the sound, and runs them from one requestAnimationFrame loop.

## Directory Structure

```
index.html            # canvas #scene and div #hud
src/
  main.ts             # reads ?seed, ?difficulty, ?palette; start screen; builds Game and Hud
  game.ts             # frame loop, layer list, autosave, postcard, day and night
  save.ts             # SaveFile shape, version, localStorage read and write
  style.css           # HUD styles, paper and ink tokens, phone breakpoints
  sim/                # simulation, no DOM or Three (ESLint enforced)
    sim.ts            # Sim class: state, commands, daily step, events
    grid.ts           # MAP_SIZE 64, idx, lines, rects, regions, distance field, road paths
    mapgen.ts         # seeded island: coast, river or lake, sand, forest, terrace heights
    types.ts          # Terrain and Zone enums
    catalogue.ts      # building definitions, costs, upkeep, capacities, tax bases
    difficulty.ts     # the three difficulty tables
    fields.ts         # service coverage, pollution, road access grids
    growth.ts         # demand, desirability, daily level and occupancy changes
    economy.ts        # monthly budget and happiness
    fire.ts           # ignition, spread, burn-out
    rng.ts            # seeded PRNG
    save.ts           # snapshot and restore of a Sim
  render/             # Three.js
    renderer.ts       # WebGLRenderer, lights, fog, EffectComposer, daylight
    camera.ts         # orthographic rig: pose, pan, zoom, quarter-turn rotation, tile picking on terraces
    layer.ts          # Layer type: sync(state, palette) and animate(dt)
    terrain.ts  water.ts  trees.ts  roads.ts  zones.ts  buildings.ts  cars.ts  fire.ts  boats.ts  birds.ts  cursor.ts
    models.ts         # procedural building geometry per zone level and service
    palette.ts        # the four palettes, role-based colours
    daylight.ts       # light cycle keyframes
    grade.ts          # vignette and grain shader
    ground.ts  roadMask.ts  geometryBuilder.ts  instanced.ts  hash.ts  random.ts
  input/
    pointer.ts        # pointer and touch tracking, one and two finger gestures
    controls.ts       # keys, edge pan, wheel, drags, pinch
    tools.ts          # BuildTool: preview plans and commits commands
    keymap.ts         # single-press key bindings
  ui/
    startScreen.ts    # difficulty, palette, seed, Continue
    hud.ts            # top bar, build menu, info and budget panels, toasts, title cards, pause menu, hints
    dom.ts  calendar.ts  swatch.ts  townName.ts
  audio/sound.ts      # Web Audio graph: sea wash, pad, plucks, chimes
tests/                # Vitest, one file per sim module, plus autoplayer.ts and helpers.ts
e2e/                  # Playwright: smoke, touch, shots (README pictures), peek (ad hoc screenshot)
scripts/mapdump.ts    # prints a generated map as text
docs/screenshots/     # README images, regenerated by npm run shots
tasks/                # spec, todo, done, lessons
```

## Runtime Flow

1. `main.ts` reads the query string, shows the start screen, and offers Continue when `readSave()` returns a valid file.
2. `new Game(canvas, start)` builds or restores the `Sim`, creates the `GameRenderer`, the `Pointer`, `CameraControls`, `BuildTool`, `Sound`, and adds every layer's object to the scene. `new Hud(root, game)` builds the DOM once.
3. Each frame: `controls.update` and `rig.update` move the camera; `tool.update` re-picks the tile under the pointer; `tick` advances the sim by whole days as the day clock allows (at most four per frame); an autosave is written when `state.rev.save` moved; layers `animate`; the HUD updates; layers `sync`; the light is set from the day fraction; the composer renders.
4. Commands come from the `BuildTool` (drag gestures) through `Sim.placeRoadLine`, `zoneRect`, `placeBuilding`, `bulldozeRect`. Each returns a `CommandResult`; the HUD turns failures into toasts and successes into sound cues.
5. `Sim.step` runs once per game day: growth, fire, happiness, then on the first of the month the budget. Milestones, fires, win and loss are queued as `SimEvent`s the HUD drains.

## Core Modules

| Module         | Path                     | Purpose                                                                                                                                               |
| -------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sim            | `src/sim/sim.ts`         | `SimState` (grids, buildings, money, status, `rev` counters), the command API with plan previews, the daily step                                      |
| Map generation | `src/sim/mapgen.ts`      | Island from simplex noise with a radial falloff, one river or lake, sand ring, forest, and terrace heights capped at `TOP_LEVEL` with one-step cliffs |
| Fields         | `src/sim/fields.ts`      | Coverage per service, pollution from industry, road access within two tiles                                                                           |
| Growth         | `src/sim/growth.ts`      | Demand per zone, desirability per tile, level and occupancy changes                                                                                   |
| Economy        | `src/sim/economy.ts`     | Monthly income, upkeep and the happiness score                                                                                                        |
| Fire           | `src/sim/fire.ts`        | Monthly ignition by difficulty, daily spread, burn-out                                                                                                |
| Renderer       | `src/render/renderer.ts` | Shadowed sun, hemisphere light, fog, bloom at night, grade pass                                                                                       |
| Camera         | `src/render/camera.ts`   | Orthographic rig with eased pose, quarter turns, picking against terrace planes                                                                       |
| Layers         | `src/render/*.ts`        | One class per visual concern, rebuilt from `state.rev` or animated per frame                                                                          |
| Build tool     | `src/input/tools.ts`     | Hover and drag into a plan preview, commit on release, cancel on a second finger                                                                      |
| HUD            | `src/ui/hud.ts`          | Everything in `#hud`, derived per frame from `game`                                                                                                   |
| Sound          | `src/audio/sound.ts`     | Started on the first gesture, suspended while muted                                                                                                   |

## Data Flow

- The sim is the single source of truth. Grids are typed arrays of `TILE_COUNT` entries; `idx(x, y)` maps a tile to its slot.
- Every command and daily change bumps the matching `state.rev` counter (`terrain`, `roads`, `zones`, `buildings`, `fire`, `save`). Layers keep the last revision they built from and rebuild only on a change, so a quiet frame uploads nothing.
- Terrain never changes after generation; its water distance field is computed once per town and shared by the terrain and boat layers.
- The autosave is `{ version, sim: snapshot, palette, camera }` in localStorage under `townlet:autosave`. `SNAPSHOT_GRIDS` lists the grids that are serialised; a save whose version or grid shape does not match is ignored.
- Daylight is a function of the sim day plus the fraction of the current day: one cycle per 120 days, with keyframes in `src/render/daylight.ts`.

## Key Integrations

- `three` 0.186: rendering, `EffectComposer`, `UnrealBloomPass`, `Timer`.
- `simplex-noise`: the land, forest and hill noise layers, seeded from the sim RNG.
- `@fontsource-variable/jost`: the HUD typeface, self-hosted.
- Web Audio: all sound is synthesised; there are no audio assets.
